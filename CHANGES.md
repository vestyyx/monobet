# MonoPredict — Change Log

This fork of **MonoBet** (upstream: https://github.com/Dvorinka/monobet) is being reworked into **MonoPredict** — a private, family-and-friends forecasting game. Sunčný, family-friendly, no gambling. Mony (Ɱ) are play points with no monetary value.

## Admin Phase 3 — Users, groups & approvals queue (committed)
- Migration `0056_users-groups.sql`: `user.banned_until / squad_role`, `squad.paused_at / invite_code / invite_enabled` (+ unique invite-code index). Temp bans self-expire: the very next authenticated action clears an expired ban (family scale, no cron).
- `lib/admin-users.ts` — pure, tested rules (13 tests; 82 green total): role-change ladder (owner untouchable, may only manage strictly below own rank, may never create a peer), ban reason/days rules (1–365), personal stake caps (`kidMode ⇒ Ɱ50 per order` on top of the admins' per-player cap and the market ceiling), invite-code format (6 chars, 0/O/1/I excluded from the generated alphabet).
- `lib/actions-admin.ts`: audited `adminSetRole`, `adminTempBan` (sessions dropped immediately), `adminUnban`, `adminForceLogout`, `adminSetKidMode`, `adminSetMaxStake`, `adminPauseSquad`, `adminRotateInviteCode`, `adminSetInviteEnabled`, `adminSetSquadParent` (one parent per squad, previous parent demoted), `adminTransferSquad`, `approvalApproveMarket`, `approvalRejectMarket` — all behind `assertRole` with a transactional "manageable target" guard (no self-touch, no owner email, no equal-or-higher rank).
- **Approvals queue:** plain players proposing a plain yes/no market land in `pending` and get "Posláno ke schválení"; staff/owners publish instantly; multi-outcome group votes stay instant. `/admin/approvals` (moderator+) approve with reason → live + opening price point (`market.approve`), reject requires a reason (`market.reject`).
- **Squads:** admin pause freezes the door AND the pot (joins, code-joins, invites, sends/contributions/loans all refuse); parent-kickable squads via new `squadKick` (parent or moderator+, debtors can't be kicked, staff needed to kick the parent); `joinSquadByCode` joins by the 6-char invite code shared by the parent; leaving a squad clears `squad_role`.
- **Pages:** `/admin/players` (q/role/status GET filters + per-row quick actions: role select, suspend with days+reason, lift, sign-out-everywhere, kid toggle, per-order cap), `/admin/groups` (squad cards: pot, members, invite code with rotate/disable, parent picker, pause/resume, owner transfer), `/admin/approvals`. Registry modules `players`/`groups`/`approvals` flipped to `built: true`.
- Player side: squad hub shows the parent crown, a kick button for the parent/staff, a paused banner and an invite-code join field; `placeTrade` enforces the personal per-order cap with a localized error ("Tady pro tebe je maximálně Ɱ 20").
- E2E on the dev instance (admtest owner + panna player, cleanup after): role promotion + demotion audited; temp ban 7 days (badge + audit), in-DB expired ban auto-lifted on panna's next action; kid mode + Ɱ20 cap set (audits `user.kidMode`/`user.maxStake`); trade Ɱ30 refused with localized cap toast, Ɱ15 bought; squad paused → contribution toast-refused, resumed; invite code `LBGZG9` generated → disabled/re-enabled (audited) → admtest joined by code; panna (parent) kicked admtest with `group.kick` audit; force-logout killed 7 sessions (`user.forceLogout`); pending yes/no proposal created → approved live with price point → second proposal rejected with reason.

## Admin Phase 2.2 — Player money + audit log (committed)

- **The core promise, kept:** every Mony change an admin makes now goes through the ledger, with a human reason, atomically, idempotently, and within per-role caps. Nobody edits `user.balance_cents` by hand; the old free-form `grantBalance` is superseded by the engine.
- Schema (migration `0055_admin-money.sql`): ledger gained `idem_key` (sparse unique index `ledger_idem_idx` — repeated submissions apply exactly once) and `batch_id` (indexed, ties bulk grants together for the one-click undo); new ledger kinds `deduct | adjust | reverse`.
- `lib/audit.ts` — the audit writer moved OUT of the `"use server"` module into a plain module so it is no longer a network-callable endpoint (closed a real security hole: previously anyone could POST to it).
- `lib/admin-money.ts` — the pure, fully-tested engine rules: role caps (moderator Ɱ1,000 / admin Ɱ10,000 per ledger row, owner uncapped), positive/target amount parsing, set-to-value difference entries, reversal math (counter-entry = minus what is left after earlier partial reversals), which kinds are reversible (only admin-created rows — never game/trade payouts), required-reason and idempotency-key rules, bulk guard (max 500 players) and preview summaries. `lib/admin-money.test.ts` covers all of it (13 tests; 69 green total).
- `lib/actions-admin.ts` ("use server"): `moneyAdjust` with ops **grant / deduct / set-to-value (difference entry) / transfer (two locked legs) / refund / reverse** — required reason (min 5 chars), per-row cap check, negative balance only when explicitly allowed by an admin+, every op audited (`money.grant … money.reverse`) with before/after balances; `freezePlayer`/unfreeze (`user.freeze`/`user.unfreeze`); `bulkGrant` for selected players / a squad / everyone (scope "all" is admin+), one ledger row per player sharing a `batchId`, one `money.bulkGrant` audit row with the affected-count+total; `bulkUndo` writes `reverse` counter-rows keyed `${batchId}:undo:${userId}`, so a second run never double-applies (admin+ only).
- **App-wide freeze enforcement:** `assertNotFrozen` added and wired into `placeTrade`, `claimDaily`, `claimRecurring` (weekly + ad), `claimBonus`, `startJobShift`, `duelPlay` and `squadSend` — a frozen player can look around but cannot move money or claim.
- Pages: **`/admin/money`** (player picker with search, all single ops + recipient select for transfers, bulk grant with preview→confirm and the batch list with undo buttons, recent admin rows, each feed row links to the player detail and offers a reverse action); **`/admin/audit-log`** (immutable log, server-side filters by action family / admin name, older/newer paging, before→after state diffs); **`/admin/players/[id]`** (profile card with balance/streak/squad, adjust + freeze island, kind-filtered transaction history, positions). Registry modules `money` + `audit-log` flipped to built; the players list stays stubbed until Phase 3.
- i18n: ~60 new keys EN+CS (`admMoney*`, `admAudit*`, `admPlayer*`), new ledger-kind labels (Odečet/Úprava/Storno) in the profile feed, and translated server-action errors ("Účet je zmrazený — admin to vyřeší" etc.).
- E2E on the dev instance (admtest owner + panna test player, cleanup after): grant Ɱ12 → ledger `grant` + audit `money.grant`; set-to-value → exact difference `adjust` row (caught and fixed a real bug here: the raw string target leaked into the delta computation); reversal of the grant row → `reverse` counter-entry, original stays visible, double-reverse correctly refuses with "Nothing left to reverse"; bulk preview "Postihne 1 hráčů — celkem Ɱ100" → confirm → idempotency keys `${batchId}:${userId}` in the DB → undo counter-row `${batchId}:undo:${userId}` (caught and fixed a sign bug — undo now debits); deduct + transfer verify both locked legs; freeze → panna's daily-claim UI refuses with localized frozen toast, `user.freeze`/`user.unfreeze` audits written; `/admin/audit-log` family filter renders all eight `money.*` rows.

## Games batch 2 — Group Polls + Word/Emoji Riddles (committed)
- New schema (migration `0053_fun-games-batch2.sql`): `poll_round` (two-option family question, minority wins) + `poll_vote` (one vote per player, switchable while open, unique index), `emoji_round` (bilingual answer + optional nudge, hint unlocks at 60 % of the round) + `emoji_attempt`. "First solver wins" is a database guarantee — a **partial unique index** (`emoji_first_solver_idx`, one `correct` row per round) makes the race for the prize airtight; the loser of the race gets a friendly "someone was a hair faster".

- `lib/actions-fun.ts`: `pollList/pollVoteRound/pollSettle` (locked settle transaction pays per vote + audit `game.pollSettle` with the tally), `emojiList/emojiGuess/emojiReveal` — answers never leave the server while a riddle is open; expired unsolved riddles settle lazily on the next list read (`revealedBy:"auto"`); admin creators `adminFunCreatePoll` / `adminFunCreateEmojiRound` (role-gated, audited).
