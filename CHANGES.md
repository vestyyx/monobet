# MonoPredict — Change Log

This fork of **MonoBet** (upstream: https://github.com/Dvorinka/monobet) is being reworked into **MonoPredict** — a private, family-and-friends forecasting game. Sunčný, family-friendly, no gambling. Mony (Ɱ) are play points with no monetary value.

## Games batch 3 — Family Quests + Photo Guess (committed)
- New schema (migration `0054_fun-games-batch3.sql`): `quest` (bilingual title/desc, fixed reward, proof kind `none | text | photo` with a localized proof ask) + `quest_claim` (one claim per quest per player — unique index; status `pending | approved | rejected`; optional note and compressed proof photo; rejected claims can be re-submitted and reset to pending), `photo_round` (compressed data-URL image, bilingual question/answer + nudge) + `photo_attempt` with the same first-solver guarantee as emoji (`photo_first_solver_idx`, one `correct` row per round). Ledger gained kind `photo` (TS-level; column is free text).
- `lib/fun.ts` + tests: `questProofNoteOk` (400-char cap), `photoDataUrlOk` (data URL of image/jpeg|png|webp under 400 KB — client compresses to ~100–250 KB on a canvas, max 1000 px edge, JPEG q=0.72), `PHOTO_MAX_ATTEMPTS = 3`, default rewards quest `Ɱ100` / photo `Ɱ200`. 56 tests passing.
- `lib/actions-fun.ts`: `questList/questClaimStart` (active quests + my claim, claims are free, proof required by kind — photo quests can't be claimed empty), `questClaimsForAdmin` (joined with users), `questReview` (approval pays through the ledger inside the transaction + audit `game.questReview` approved; rejection resets review stamps so it can be re-submitted), `adminFunCreateQuest` (audit `game.questCreate`); `photoList` (lazy auto-close for expired unsolved rounds, `revealedBy:"auto"`), `photoGuess` (diacritic-insensitive typed answers via the shared emoji normalizer, answers never ship while open, race loser gets a friendly "someone was a hair faster"), `photoReveal` (audit `game.photoReveal`), `adminFunCreatePhotoRound` (audit `game.photoCreate`; nudge at 60 % of the round, close capped 1 h–30 d).
- Player pages `/quests` (claim/resubmit states, own-status badges, compressed photo upload with preview) and `/photo` (big photo card, three guesses, nudge block, winner line) + `/games` hub now shows all 6 live cards. Ledger kind labels for `photo` added to the profile feed (CZ/EN).
- Admin: `/admin/quests` (quest creator + review desk — pending claims first with proof-photo thumbs, approve-and-pay / send-back,-reviewed history) and `/admin/photo-guess` (pick photo → auto-compress preview → publish with bilingual answers/hints/reward; round list with guess counts and reveal), registry modules `quests` + `photo-guess` flipped to `built: true`.
- Demo seed extended: one open trust-proof quest ("Vynes odpad v den svozu / Take out the recycling…") and one open photo round with a generated demo JPEG (`scripts/seed-photo-dataurl.txt`, regenerated by `scripts/gen-seed-photo.ps1`), both idempotent; new inspector `scripts/check-batch3.ts`.
- E2E on the dev instance: quest claim → "waiting for the parent's review" → admin approve toast "+Ɱ 120" → ledger row `quest` +Ɱ120 + audit `game.questReview` approved; photo round wrong guess burns an attempt (toast "Ne-e. Zbývají 2 tipy"), correct guess "colorful bubbles!!!" settles and pays Ɱ200 `photo`, audit `game.photoReveal`; admin quest create (`game.questCreate`) and photo upload→compress→publish (`game.photoCreate`) both driven through the real UI.

## Games batch 2 — Group Polls + Word/Emoji Riddles (committed)
- New schema (migration `0053_fun-games-batch2.sql`): `poll_round` (two-option family question, minority wins) + `poll_vote` (one vote per player, switchable while open, unique index), `emoji_round` (bilingual answer + optional nudge, hint unlocks at 60 % of the round) + `emoji_attempt`. "First solver wins" is a database guarantee — a **partial unique index** (`emoji_first_solver_idx`, one `correct` row per round) makes the race for the prize airtight; the loser of the race gets a friendly "someone was a hair faster".
- `lib/fun.ts` + tests: `pollMinoritySide` (smaller side wins in full, a tie crowns BOTH sides, empty poll pays nobody), `emojiSolves`/`emojiNormalize` (answers compare case-, diacritic-, punctuation- and whitespace-insensitively — "PAPANČE with jam!!!" counts), `emojiAttemptsLeft` (3 attempts), `funRoundOpen`, rewards `Ɱ100` per minority voter, `Ɱ150` first solver. 54 tests passing.
- `lib/actions-fun.ts`: `pollList/pollVoteRound/pollSettle` (locked settle transaction pays per vote + audit `game.pollSettle` with the tally), `emojiList/emojiGuess/emojiReveal` — answers never leave the server while a riddle is open; expired unsolved riddles settle lazily on the next list read (`revealedBy:"auto"`); admin creators `adminFunCreatePoll` / `adminFunCreateEmojiRound` (role-gated, audited).
- Player pages `/poll` (vote, switch sides until close, live tallies, winners line) and `/emoji` (three guesses, nudge block, first-solver name) + `/games` hub now shows 4 live cards.
- Admin: `/admin/polls` and `/admin/word-guess` (creators + round lists incl. vote/guess counts via grouped side queries, close-and-pay / reveal buttons), registry modules `polls` + `word-guess` flipped to `built: true`.
- Demo seed `scripts/seed-fun.ts` extended (open family poll ×2, one open emoji riddle) + new inspectors `scripts/check-fun.ts` / `scripts/check-users.ts`.
- E2E on the dev instance: vote A↔B switching, minority/tie settle paying both sides Ɱ100 each, first-solver race (wrong guess burns an attempt, correct guess settles the round and pays Ɱ150), admin create + reveal with `game.*` audit rows.

### 2.1 Architecture + module registry (committed)
- `lib/admin/rbac.ts` — role ladder **user → moderator → admin → owner** (super-admin email = owner), `requireRole`/`assertRole` as the single server-side gate for every admin endpoint.
- `lib/admin/modules.ts` — **module registry**: markets, gigs, all planned family games, money, groups, moderation, approvals, economy, settings, audit-log — each with CZ/EN labels, icon, minimum role and delivery phase. Sidebar, dashboard quick links and section routing generate from it (adding/flagging a module updates the whole panel).

- New shell: registry-driven sidebar (responsive, tablet-friendly), **live dashboard** `/admin` (active today, supply, trades/gigs/duels today, pending approvals, reports, recent money movement, warnings) and `/admin/[section]` stubs for not-yet-built modules. The original stacked panels remain at `/admin/overview` until phases 3–6 migrate them.
